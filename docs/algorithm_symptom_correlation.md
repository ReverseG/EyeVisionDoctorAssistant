# 眼底 AI 系统算法设计与验证文档

> 辅助诊断参考，不替代医生最终诊断
> 文档版本：v2.0
> 最后更新：2026-04-02

---

## 1. 文档定位

本文档用于定义算法部分的一期可交付范围、数据要求、评估方法、上线流程和风险控制方式。

本次版本不再把“多模态复杂关联模型”作为一期上线前提，而是拆分为三个层次：

- 一期上线能力：眼底/ OCT 结构化分析能力
- 二期增强能力：医生报告症状抽取
- 二期研究能力：图像与症状关联分析

这样做的目标是降低研发与验证耦合度，保证系统可以先形成临床可用闭环。

---

## 2. 范围定义

### 2.1 一期上线算法范围

一期正式交付只包含以下算法任务：

- 图像质量评估
- 眼底彩照 DR 分级
- 病变检测
- OCT 分层与关键参数量化

### 2.2 二期增强范围

- 医生报告症状抽取
- 结构化病历字段清洗与标准化
- 统计关联分析看板

### 2.3 二期预研范围

- 复杂多模态关联评分
- 图神经网络关联建模
- 文献证据自动检索与证据链融合

---

## 3. 算法总体原则

- 先可验证，再复杂化
- 先结构化输出，再做综合评分
- 先支持医生审核，再考虑自动建议
- 任何模型结论都必须绑定模型版本、阈值版本和数据版本
- 不把未经充分验证的关联分析结果作为临床结论输出

---

## 4. 一期算法架构

```text
Raw Image / OCT
    ↓
Pre-check
  - 文件格式校验
  - 元数据解析
  - 去重校验
    ↓
Quality Assessment
  - 清晰度
  - 曝光
  - 视野范围
  - 遮挡
    ↓
Preprocessing
  - 标准化
  - 尺寸归一
  - 去噪/增强
    ↓
Task Models
  - DR Grading
  - Lesion Detection
  - OCT Layer Segmentation
  - OCT Biomarker Quantification
    ↓
Post-processing
  - 阈值过滤
  - 规则修正
  - 结构化结果生成
    ↓
Output Package
  - 结构化 JSON
  - 可视化热力图/标注
  - 模型元数据
```

## 5. 一期任务设计

### 5.1 图像质量评估

#### 目标

识别不适合进入推理的样本，减少误判和无效分析。

#### 输出

```json
{
  "is_qualified": true,
  "quality_score": 0.91,
  "failure_reasons": []
}
```

#### 关键维度

- 清晰度不足
- 曝光过度 / 欠曝
- 视野不完整
- 遮挡、反光、睫毛干扰
- 非目标模态或文件损坏

#### 上线原则

- 质量不合格不进入正式分析
- 失败原因必须可展示给上传人员

### 5.2 眼底彩照 DR 分级

#### 目标

输出左眼/右眼 DR 分级和分级置信度。

#### 输出字段

- eye_side
- dr_grade
- confidence
- model_version
- threshold_version

#### 说明

- 一期只输出模型支持的固定分级体系
- 页面需展示“供医生审核”的标识

### 5.3 病变检测

#### 目标

检测和统计关键病变，服务于医生审核和报告展示。

#### 一期病变范围

- 微动脉瘤
- 出血点
- 硬性渗出
- 软性渗出

#### 输出字段

```json
{
  "lesions": [
    {
      "eye_side": "left",
      "type": "microaneurysm",
      "count": 12,
      "confidence": 0.92,
      "boxes": [[120, 80, 24, 24]]
    }
  ]
}
```

### 5.4 OCT 分层与量化

#### 目标

输出结构化 OCT 指标，为医生判断和纵向随访提供参考。

#### 一期输出

- 视网膜总厚度
- 各层厚度
- 黄斑相关液体或水肿量化指标
- 关键可视化图

#### 注意

- 文档中不把“所有 OCT 能力”一次性承诺为上线目标
- 若杯盘比算法尚未成熟，可作为预留字段，不纳入一期验收

## 7. 数据设计

### 7.1 数据来源

一期算法使用以下数据：

- 眼底彩照历史样本
- OCT 历史样本
- 医生审核结果
- 病变标注数据

二期新增：

- 医生自由文本报告
- 主诉、病史、检验等结构化字段

### 7.2 数据集拆分原则

- 按患者维度拆分，禁止同患者跨训练/验证/测试集合
- 按设备、医院、时间段做分层采样
- 单独保留外部测试集或后验验证集

### 7.3 数据纳入标准

- 模态明确且文件可解析
- 患者与检查信息可关联
- 标签来源清晰
- 原始文件可追溯

### 7.4 数据排除标准

- 文件损坏或模态错误
- 重复样本无法区分
- 标签冲突且未仲裁
- 关键元数据缺失

## 8. 标注与质控

### 8.1 标注对象

- DR 分级标签
- 病变框或分割区域
- OCT 关键层与区域
- 质量问题标签

### 8.2 标注流程

1. 初标
2. 复核
3. 仲裁
4. 归档

### 8.3 质控要求

- 每批次抽检不少于 10%
- 对高风险标签进行双人复核
- 保存标注工具版本和导出时间
- 记录标签变更原因

### 8.4 标签一致性指标

- DR 分级一致率
- 病变标注 IoU 一致性
- 标注员间 Kappa

---

## 9. 训练与验证策略

### 9.1 一期训练原则

- 每个任务单独训练、单独评估
- 不做跨任务综合分数作为上线门槛
- 先使用稳定基线模型，优先保证复现与验证

### 9.2 验证集与测试集

- 验证集用于选模型与调阈值
- 测试集用于冻结后评估
- 临床试运行集不得参与训练调参

### 9.3 阈值策略

- 每个模型独立维护阈值版本
- 阈值由验证集确定
- 阈值调整必须记录变更单和影响分析

## 10. 一期评估指标

### 10.1 质量评估模型

| 指标 | 目标 |
|------|------|
| Qualified/Unqualified F1 | >= 0.90 |
| 不合格样本召回率 | >= 0.95 |

### 10.2 DR 分级模型

| 指标 | 目标 |
|------|------|
| 多分类准确率 | >= 0.85 |
| Macro F1 | >= 0.82 |
| 高风险等级召回率 | >= 0.90 |
| 校准误差 ECE | 可统计并持续优化 |

### 10.3 病变检测模型

| 指标 | 目标 |
|------|------|
| mAP | >= 既定基线 |
| 病变级召回率 | 对高风险病变优先保证召回 |
| 误报率 | 按病变类型分别统计 |

### 10.4 OCT 任务

| 指标 | 目标 |
|------|------|
| 分层 Dice / IoU | >= 既定基线 |
| 厚度 MAE | <= 既定基线 |
| 临床关键指标一致性 | 与专家测量对齐 |

### 10.5 上线前附加评估

- 不同设备分层评估
- 不同医院分层评估
- 不同图像质量分层评估
- 左眼/右眼分层评估
- 误报、漏报案例集分析

## 11. 医生报告症状抽取设计（二期增强）

### 11.1 目标

从医生书写的诊断文本中抽取结构化症状、体征、病变、诊断与时间信息，服务于报告规范化和后续统计分析。

### 11.2 二期定位

该模块在二期作为“辅助结构化录入”能力，不直接进入正式诊断结论生成链路。

### 11.3 输入输出

输入：

- 自由文本报告

输出：

- 实体列表
- 关系列表
- 结构化 JSON
- 高亮溯源片段

### 11.4 技术路线

建议采用分层实现，而不是一步到位追求复杂端到端模型：

1. 规则与词典基线
2. NER 模型
3. 关系抽取模型
4. 人工审核修正界面

### 11.5 二期评估指标

| 指标 | 目标 |
|------|------|
| NER Precision | >= 0.90 |
| NER Recall | >= 0.88 |
| NER F1 | >= 0.89 |
| 端到端结构化准确率 | >= 0.82 |

### 11.6 二期上线限制

- 抽取结果默认标记为“待人工确认”
- 不可直接覆盖医生原文
- 必须保留来源句子和置信度

## 12. 图像与症状关联分析设计（二期研究）

### 12.1 问题定义

研究图像特征与临床症状、病史、检验指标之间的统计关联，为科研分析和质控看板提供支持。

### 12.2 不作为一期上线能力的原因

- 真值定义困难
- 综合分数解释成本高
- 临床误用风险高
- 与报告主闭环耦合度过大

### 12.3 推荐实施顺序

1. 结构化字段整理
2. 单变量和多变量统计分析
3. 可解释可审查的关联展示
4. 再考虑更复杂的融合模型

### 12.4 推荐的一版方案

二期先做以下可解释方案：

- Spearman / Pearson 相关分析
- Logistic / Linear Regression
- 分层统计与混杂因素控制
- 关联网络图与证据说明

### 12.5 暂不建议直接上线的方案

- 固定权重融合的综合关联分
- 无充分验证的 GNN 临床评分
- 自动生成“因果式”解释结论

## 13. 推理服务与上线流程

### 13.1 推理服务原则

- 采用异步任务处理
- 返回结构化结果而非直接返回最终报告
- 模型服务与业务服务解耦

### 13.2 上线流程

1. 数据冻结
2. 训练完成
3. 验证与阈值确定
4. 测试集评估
5. 医学顾问复核
6. 生成模型卡和发布说明
7. 灰度或院内试运行
8. 正式切换

### 13.3 每次发布必须输出

- 模型版本号
- 数据快照号
- 指标报告
- 阈值说明
- 已知风险清单
- 回滚版本

---

## 14. 线上监控

### 14.1 监控项

- 推理成功率
- 推理耗时 P50/P95
- 各模型调用量
- 质量不合格率
- 高风险等级占比波动
- 医生驳回率
- 医生人工修改率

### 14.2 漂移预警信号

- 输入分布显著变化
- 高风险类别比例异常上升或下降
- 医生驳回率持续升高
- 某设备来源样本错误率异常

### 14.3 触发动作

- 预警通知
- 暂停新版本放量
- 回切上一稳定版本
- 启动样本复盘

---

## 15. 回滚与异常处理

### 15.1 回滚条件

- 线上关键指标明显恶化
- 医生驳回率超阈值
- 某类病变漏检风险升高
- 模型服务稳定性异常

### 15.2 回滚策略

- 保留上一稳定模型版本
- 业务服务支持按任务类型切换模型版本
- 报告中已生成结果保留原版本信息，不做静默覆盖

---

## 16. 合规与安全要求

- 训练数据必须脱敏
- 训练集、验证集、测试集来源可追溯
- 模型输出不得替代医生签发
- 所有算法输出必须可绑定到原始影像和版本信息
- 面向质控和科研的分析结果应默认脱敏展示

## 17. 实施计划

### Phase A：一期正式交付（6-8 周）

- 图像质量评估
- DR 分级
- 病变检测
- OCT 关键量化
- 统一结构化输出
- 模型版本管理

### Phase B：临床试运行优化（4 周）

- 阈值调整
- 分层评估
- 误报漏报复盘
- 医生反馈收集

### Phase C：二期增强（6-8 周）

- 症状抽取
- 报告结构化辅助
- 统计关联看板

### Phase D：二期研究（持续）

- 高级多模态建模
- 复杂关联解释
- 科研型分析模块

---

## 18. 主要风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 标注质量不稳定 | 高 | 双人复核和仲裁机制 |
| 训练集与上线场景偏差 | 高 | 分层评估和院内试运行 |
| 模型过拟合离线数据 | 高 | 保留独立测试集和后验验证集 |
| 医生对结果不信任 | 高 | 保留热力图、病变标注、版本信息和审核闭环 |
| 复杂关联分析被误读 | 高 | 二期仅作为科研/统计辅助，不作为主诊断依据 |
| 阈值频繁调整不可追溯 | 中 | 独立维护阈值版本和发布记录 |
